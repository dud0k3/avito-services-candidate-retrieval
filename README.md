# Кандидатогенерация объявлений услуг

Задача: вернуть до 50 объявлений для каждого поискового запроса. Качество
оценивается по Recall@50: попало ли объявление, выбранное пользователем, в эти
50 кандидатов. Порядок внутри списка на метрику не влияет.

## Подход

Я использовал четыре текстовых сигнала:

1. TF-IDF по словам и парам слов в заголовке объявления.
2. TF-IDF по символьным фрагментам заголовка (3–5 символов). Он помогает с
   разными формами слов и мелкими опечатками.
3. TF-IDF по заголовку, параметрам и началу описания. Заголовок повторён
   дважды, чтобы длинное описание не вытесняло название услуги.
4. TF-IDF по фильтрам запроса и параметрам объявления. Например, выбранный
   пользователем вид услуги можно сопоставить с видом услуги в объявлении.

Каждый сигнал предлагает до 150 объявлений по всему корпусу и до 150 из
локации запроса. Из их объединения CatBoost выбирает финальные 50. На вход
ему идут четыре значения текстового сходства, совпадение локаций, доля слов
запроса в заголовке, точное вхождение запроса, рейтинг и число отзывов,
длина заголовка, длина запроса и наличие фильтра.

Для обучения CatBoost я выбрал 1200 поисковых контекстов из `train.parquet`.
Положительные пары — выбранные пользователями объявления. Отрицательные —
похожие объявления, найденные первым этапом, но не выбранные в этих
контекстах. На один запрос беру 200 кандидатов с высоким исходным скором и
ещё 50 случайных из остальных. Это позволяет модели учиться на трудных
альтернативах. Параметры модели: 500 итераций, глубина 6, learning rate 0,05.

В итоговом списке сначала беру лучшие объявления из локации запроса; если их
меньше 50, дополняю объявлениями из других локаций. В обучающих парах около
83% выбранных объявлений имеют тот же `location_id`, что и запрос. Локальное
ограничение помогает общей полноте, но может пропустить объявление в соседнем
городе.

`search_category` почти всегда равен 114, а флаг доставки в запросах
бенчмарка всегда нулевой. Поэтому они не участвуют в итоговом скоре.

Решение использует `pandas`, `NumPy`, `SciPy`, `scikit-learn`, `PyArrow` и
`CatBoost`. Предобученных языковых моделей и внешних API нет. Бинарный файл
`reranker.cbm` включён для точного повторения ответа; код обучения есть в
`rerank.py`.

## Локальная проверка

Я взял 600 случайных уникальных сочетаний признаков запроса из `train.parquet`
с фиксированным seed 42. Релевантными считал все уникальные `item_id`,
выбранные по такому сочетанию. Корпусом были все 344 825 уникальных объявлений
из `train.parquet`. Это позволяет проверить Recall@50: большинство выбранных
объявлений из `train.parquet` отсутствует в `benchmark_items.parquet`.
Перед обучением CatBoost проверочные сочетания запросов исключались из его
обучающей выборки.

| Проверочные запросы | Текстовый скор | CatBoost |
| --- | ---: | ---: |
| 600 запросов, seed 42 | 0,7509 | **0,7659** |
| 300 запросов, seed 123 | 0,7006 | **0,7074** |

На обеих выборках CatBoost улучшил Recall@50. Я также проверял смесь рангов
CatBoost и исходного скора. Оптимальный вес отличался между выборками, поэтому
для финального ответа выбрал CatBoost без дополнительного смешивания. Это
локальные оценки, а не результат на скрытых запросах бенчмарка. Проверочный
корпус больше бенчмарк-корпуса, поэтому числа не обязаны совпадать.

На примерах ошибок видны два случая. Иногда подходящее объявление находится
среди нескольких сотен кандидатов, но не входит в финальные 50. Именно этот
случай частично исправил CatBoost. Иногда объявление вообще не попадает в
текстовую выдачу: запрос и объявление описывают одну услугу разными словами,
например «снять беседку» и «аренда беседки». Я проверил локальную модель
эмбеддингов: она расширила набор найденных объявлений, но почти не улучшила
итоговый Recall@50, поэтому не включил её в решение.

При просмотре выдачи бенчмарка заметил ещё один тип ошибки: редкий уточняющий
термин может потеряться на фоне общего названия услуги. Например, для
«4-стоечного подъёмника» среди первых кандидатов оказались и другие виды
подъёмников. Ручных исправлений отдельных запросов в ответе нет.

## Запуск

Нужны три Parquet-файла в одном каталоге: `train.parquet`,
`benchmark_queries.parquet`, `benchmark_items.parquet`. Данные в репозиторий
не включены.

```bash
python -m pip install -r requirements.txt
python retrieval.py --data-dir /path/to/data --validate
python validate_rerank.py --data-dir /path/to/data --train-queries 1200 --validation-queries 600 --seed 42
python rerank.py --data-dir /path/to/data --model reranker.cbm --output answer.csv
```

Последняя команда создаёт `answer.csv` без индекса и проверяет состав
запросов, допустимость `item_id`, отсутствие повторов и ограничение в 50
кандидатов. Чтобы заново обучить модель из исходных данных, добавь флаг
`--retrain`. Для второй локальной проверки использовались
`--validation-queries 300 --seed 123`.
