# Решение тестового задания Авито

Репозиторий содержит код для поиска до 50 объявлений по каждому запросу. Основная метрика задания — Recall@50: какая доля выбранных пользователями объявлений попала в эти 50.

## Какие данные и признаки я использовал

В `train.parquet` находятся запросы и объявления, которые выбирали пользователи. Я использовал эти пары для обучения CatBoost и проверки качества.

Для поиска по benchmark используются `benchmark_queries.parquet` и `benchmark_items.parquet`. В них находятся запросы и объявления, среди которых нужно искать ответы.

В поиске используются:

- текст запроса и фильтры, например вид услуги;
- заголовок, параметры и начало описания объявления;
- город поиска и город объявления;
- рейтинг объявления и число отзывов.

Текстовые поля нужны, чтобы найти объявления с подходящей услугой. Город помогает учитывать расстояние до исполнителя. Рейтинг и отзывы используются CatBoost при выборе финальных объявлений.

## Как устроено решение

Сначала четыре TF-IDF поиска находят объявления по словам заголовка, похожим кусочкам слов, полному тексту объявления и параметрам услуги. Каждый поиск предлагает до 150 объявлений по всему корпусу и до 150 из города запроса. Затем CatBoost оценивает пары «запрос — объявление» и оставляет до 50 объявлений.

CatBoost обучен на парах из `train.parquet`. Положительными примерами служат выбранные объявления. В качестве отрицательных примеров я использовал похожие объявления с высокими поисковыми оценками и случайные кандидаты. Веса модели сохранены в `reranker.cbm`, поэтому для создания ответа переобучать модель не нужно.

## Как я проверял качество

Я делил данные по поисковым контекстам: запросы для проверки не использовались при обучении соответствующей модели. Ниже результаты на `train.parquet`. Seed и размер проверки указаны для каждого результата: разные строки с разными seed напрямую сравнивать нельзя.

| Модель или вариант поиска | Проверка | Recall@50 |
| --- | --- | ---: |
| TF-IDF поиск | 600 запросов, seed 42 | 0,7509 |
| TF-IDF + CatBoost | 600 запросов, seed 42 | **0,7659** |
| TF-IDF поиск | 600 запросов, seed 17 | 0,7418 |
| TF-IDF + CatBoost | 600 запросов, seed 17 | 0,7537 |
| TF-IDF поиск | 300 запросов, seed 123 | 0,7006 |
| TF-IDF + CatBoost | 300 запросов, seed 123 | 0,7074 |
| Готовая MiniLM без дообучения, dense-поиск | 600 запросов, seed 42 | 0,5627 |
| TF-IDF + готовая MiniLM | 600 запросов, seed 42 | 0,7517 |
| Дообученная MiniLM, dense-поиск | 600 запросов, seed 17 | 0,7700 |
| TF-IDF + дообученная MiniLM, смешанные ранги | 600 запросов, seed 17 | **0,7845** |
| TF-IDF + MiniLM + CatBoost | 600 запросов, seed 17 | 0,7631 |
| TF-IDF + BM25 + CatBoost | 600 запросов, seed 17 | 0,7388 |
| CatBoostRanker + MiniLM, смешанные ранги | 600 запросов, seed 17 | 0,7806 |
| TF-IDF + MiniLM, RRF | 600 запросов, seed 17 | 0,7742 |
| TF-IDF + MiniLM, отдельные ранги текстовых полей | 600 запросов, seed 17 | 0,7809 |
| TF-IDF + MiniLM, вес подобран на первых 300 запросах | первые 300: 0,8009; следующие 300: 0,7629 | 0,7819 на всех 600 |
| Похожие прошлые запросы + MiniLM | 600 запросов, seed 17 | 0,7675 |

Лучший общий локальный результат — **0,7845**. Он получен со смешиванием TF-IDF и дообученной MiniLM. В `answer.csv` сохранён ответ, построенный этим вариантом. На benchmark нет ответов пользователей, поэтому его настоящий Recall@50 посчитать нельзя. Подбор веса на первых 300 запросах дал на них 0,8009, но на следующих 300 результат упал до 0,7629, поэтому считать 0,8 устойчивым результатом нельзя. Все сравнения и ограничения описаны в [EXPERIMENTS.md](EXPERIMENTS.md).

Отдельно проверял полноту большого списка кандидатов до отбора финальных 50: она выросла с 0,8614 у TF-IDF до 0,8981 у TF-IDF + MiniLM. Это другая метрика; она не означает, что финальный Recall@50 равен 0,8981.

## Какие ошибки я нашёл

- **Нужное объявление не находилось по словам.** Например, пользователь пишет услугу другими словами. Добавление MiniLM увеличило полноту большого списка кандидатов; в проверке на seed 17 доля найденных подходящих объявлений в этом списке выросла с 0,8614 до 0,8981.
- **Нужное объявление находилось, но не попадало в финальные 50.** Поэтому я проверял CatBoost и смешивание рангов. В лучшем эксперименте Recall@50 был 0,7845, то есть часть объявлений всё ещё терялась при отборе.
- **BM25 добавлял несколько новых объявлений, но CatBoost не всегда правильно поднимал их.** На проверке итоговый Recall@50 снизился с 0,7537 до 0,7388, поэтому BM25 не включён в решение для отправки.
- **В данных есть только выбранные объявления.** Объявление, которое не выбрали, не обязательно было плохим. Я использовал сложные и случайные отрицательные примеры, но это ограничение разметки полностью устранить нельзя.
- **Формат идентификаторов легко испортить.** Код сохраняет `query_id` и `item_id` как строки и проверяет их формат, наличие в корпусе, повторы и лимит в 50 объявлений.

## Как получить `answer.csv`

Скачайте три файла задания и положите их в папку `data` рядом с файлами репозитория:

```text
data/
  train.parquet
  benchmark_queries.parquet
  benchmark_items.parquet
```

Установите зависимости, обучите MiniLM и запустите поиск. Первое обучение и запуск могут занять некоторое время:

```bash
python3 -m pip install -r requirements.txt -r requirements-transformers.txt
python3 finetune_minilm.py --data-dir ./data \
  --model-dir sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2 \
  --output-dir ./artifacts/minilm-seed17 --max-pairs 20000 \
  --epochs 2 --batch-size 32 --seed 17
python3 predict_minilm_blend.py --data-dir ./data \
  --model-dir ./artifacts/minilm-seed17 --output ./answer.csv --device mps
```

Для Mac используется `--device mps`, для видеокарты NVIDIA — `--device cuda`, для обычного процессора — `--device cpu`. После загрузки открытой модели и пакетов обработка данных идёт локально. Скрипт проверяет количество запросов, формат и наличие ID, повторы и ограничение в 50 объявлений.

Для дообучения используется открытая модель `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`. Её веса не хранятся в Git из-за размера. После загрузки модели и библиотек скрипт работает локально, без внешнего API. Приложенный `answer.csv` уже готов; команды выше нужны, чтобы снова обучить модель и собрать новый ответ тем же способом.

Предыдущий вариант с CatBoost тоже сохранён и доступен этой командой:

```bash
python3 rerank.py --data-dir ./data --model ./reranker.cbm --output ./answer_catboost.csv
```

Чтобы отдельно проверить CatBoost на обучающих данных, запустите:

```bash
python3 validate_rerank.py --data-dir ./data --train-queries 1200 --validation-queries 600 --seed 17
```

Этот запуск обучит проверочную модель на 1 200 контекстах и сравнит её с лексическим поиском на других 600 контекстах. Он нужен для проверки качества и не используется для создания benchmark-ответа.

## Файлы

- `rerank.py` — создаёт отдельный ответ с CatBoost.
- `predict_minilm_blend.py` — создаёт `answer.csv` с лучшим локально проверенным вариантом TF-IDF + MiniLM.
- `answer.csv` — готовые до 50 `item_id` для каждого benchmark-запроса.
- `retrieval.py` — ищет кандидатов с помощью TF-IDF и проверяет формат ответа.
- `reranker.cbm` — сохранённая модель CatBoost для воспроизведения ответа.
- `validate_rerank.py` — локальная проверка качества.
- `EXPERIMENTS.md` — подробные сравнения и заметки о ходе экспериментов.
