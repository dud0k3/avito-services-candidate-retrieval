# Решение тестового задания Авито

Репозиторий содержит код для поиска до 50 объявлений по каждому запросу. Основная метрика задания — Recall@50: какая доля выбранных пользователями объявлений попала в эти 50.

## Какие данные и признаки я использовал

В `train.parquet` находятся запросы и объявления, которые выбирали пользователи. Я использовал эти пары для обучения CatBoost и проверки качества.

Для поиска по benchmark используются `benchmark_queries.parquet` и `benchmark_items.parquet`. В них находятся запросы и объявления, среди которых нужно искать ответы.

В поиске используются:

- текст запроса и фильтры, например вид услуги;
- заголовок, параметры и начало описания объявления;
- город поиска и город объявления;
- рейтинг объявления и число отзывов.

Текстовые поля нужны, чтобы найти объявления с подходящей услугой. Город помогает учитывать расстояние до исполнителя. Рейтинг и отзывы используются CatBoost при выборе финальных объявлений.

## Как устроено решение

Сначала четыре TF-IDF поиска находят объявления по словам заголовка, похожим кусочкам слов, полному тексту объявления и параметрам услуги. Каждый поиск предлагает до 150 объявлений по всему корпусу и до 150 из города запроса. Затем CatBoost оценивает пары «запрос — объявление» и оставляет до 50 объявлений.

CatBoost обучен на парах из `train.parquet`. Положительными примерами служат выбранные объявления. В качестве отрицательных примеров я использовал похожие объявления с высокими поисковыми оценками и случайные кандидаты. Веса модели сохранены в `reranker.cbm`, поэтому для создания ответа переобучать модель не нужно.

## Как я проверял качество

Я делил данные по поисковым контекстам: контексты для проверки не использовались при обучении соответствующей модели. На 600 запросах с seed 17 TF-IDF + CatBoost дали Recall@50 **0,7537**. На другой выборке из 600 запросов с seed 42 результат составил **0,7659**. Это локальная проверка на `train.parquet`, а не результат скрытого benchmark.

Также я проверил BM25 и готовую и дообученную MiniLM. Лучший локальный результат получился у смешивания рангов TF-IDF и дообученной MiniLM — **0,7845** на 600 запросах с seed 17. Этот вариант не входит в сохранённую модель для отправки. Все сравнения и ограничения описаны в [EXPERIMENTS.md](EXPERIMENTS.md).

## Какие ошибки я нашёл

- **Нужное объявление не находилось по словам.** Например, пользователь пишет услугу другими словами. Добавление MiniLM увеличило полноту большого списка кандидатов; в проверке на seed 17 доля найденных подходящих объявлений в этом списке выросла с 0,8614 до 0,8981.
- **Нужное объявление находилось, но не попадало в финальные 50.** Поэтому я проверял CatBoost и смешивание рангов. В лучшем эксперименте Recall@50 был 0,7845, то есть часть объявлений всё ещё терялась при отборе.
- **BM25 добавлял несколько новых объявлений, но CatBoost не всегда правильно поднимал их.** На проверке итоговый Recall@50 снизился с 0,7537 до 0,7388, поэтому BM25 не включён в решение для отправки.
- **В данных есть только выбранные объявления.** Объявление, которое не выбрали, не обязательно было плохим. Я использовал сложные и случайные отрицательные примеры, но это ограничение разметки полностью устранить нельзя.
- **Формат идентификаторов легко испортить.** Код сохраняет `query_id` и `item_id` как строки и проверяет их формат, наличие в корпусе, повторы и лимит в 50 объявлений.

## Как повторить отправленный результат

Скачайте три файла задания и положите их в папку `data` рядом с файлами репозитория:

```text
data/
  train.parquet
  benchmark_queries.parquet
  benchmark_items.parquet
```

Установите зависимости и запустите поиск:

```bash
python3 -m pip install -r requirements.txt
python3 rerank.py --data-dir ./data --model ./reranker.cbm --output ./answer.csv
```

Скрипт читает ту же сохранённую CatBoost-модель, строит список кандидатов и сохраняет `answer.csv` с двумя колонками: `query_id` и `answer`. Перед сохранением он проверяет количество запросов, формат и наличие ID, повторы и ограничение в 50 объявлений. Код не обращается к внешним API.

Я запустил эту команду на данных из задания и сравнил файл с подготовленным `answer.csv`: совпали все 2 452 строки и все списки объявлений. Совпал и SHA-256 файла.

Чтобы отдельно проверить CatBoost на обучающих данных, запустите:

```bash
python3 validate_rerank.py --data-dir ./data --train-queries 1200 --validation-queries 600 --seed 17
```

Этот запуск обучит проверочную модель на 1 200 контекстах и сравнит её с лексическим поиском на других 600 контекстах. Он нужен для проверки качества и не используется для создания benchmark-ответа.

## Файлы

- `rerank.py` — обучает CatBoost и создаёт `answer.csv`.
- `retrieval.py` — ищет кандидатов с помощью TF-IDF и проверяет формат ответа.
- `reranker.cbm` — сохранённая модель CatBoost для воспроизведения ответа.
- `validate_rerank.py` — локальная проверка качества.
- `EXPERIMENTS.md` — подробные сравнения и заметки о ходе экспериментов.
